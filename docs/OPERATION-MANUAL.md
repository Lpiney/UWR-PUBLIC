## Mission 1：通訊配對（20 分）

**要做的**：ROV 自己連上塔、自己把一串字抓回來，唸給裁判聽。
**筆電只負責顯示**，不能碰網路。

> 大會另外公告：**只能用 ESP32，不准用手機或電腦瀏覽器**；支援 TCP 和 HTTP GET/POST，
> **不支援 UDP**。我們用 HTTP GET。
> 筆電端**完全沒有 HTTP 能力**（沒裝任何網路庫），想違規都做不到。

### 一、接線並設定位址

大會公布的是 **IP 和 port**（例如 `192.168.4.1`、`8080`），有路徑也要帶上。

1. 板子用 USB 線接上筆電
2. 開序列埠監視器，鮑率 **115200**

   （Windows 上怎麼找埠、怎麼開，見[這份](Operation-Manuals/Windows-Serial-Console.md)）
3. 打這行，按 Enter：

   ```
   P url 192.168.4.1:8080
   ```

   （換成大會給的 IP:port；有路徑就寫 `192.168.4.1:8080/api/data`）

4. 看到這行就對了：

   ```
   OK P url = http://192.168.4.1:8080
   ```

   **少了 `http://` 沒關係**，程式會自己補，並把補完的結果印在 `OK` 那行給你看。

5. **關掉序列埠監視器**（一定要關，不然下一個程式開不了）

> ⚠️ **port 一定要打。** 只寫 IP 的話程式會去連 80 埠，
> 伺服器不在 80 就會失敗，而錯誤訊息不會告訴你是 port 的問題。

> 位址存在板子裡，斷電和重燒都不會掉。**一天只要設一次**，
> 已經設過就跳到第二步。但**每天進場前還是 `G url` 確認一次**——
> 大會公布的位址可能變。

> ⚠️ **不要送 `R`。** 它會把校準過的配平、中立位全部清掉。

> **SSID 和密碼不用設。** `UR_Field` / `12345678` 是編譯進去的預設值。
> 只有大會臨時改掉才需要 `P ssid` / `P pass`。

### 二、開操作台

1. 在筆電上執行：

   ```bash
   python3 host/console.py
   ```

2. 等左上角出現**綠燈 ● LINK**

### 三、抓資料

1. **按手柄上的 X**

   板子會立刻抓一次，不用等。

2. 看左下角，這三行都要對：

   ```
   wifi CONNECTED
   http 200
   DATA [Congratulations!!! This is the WiFi API task message for the fall training.]
   ```

3. 把 `DATA` 那行唸給裁判聽

### 沒成功時

| 看到 | 怎麼辦 |
|---|---|
| `wifi CONNECTING` 超過 30 秒不動 | 板子離塔太遠。等一下它會自己重試 |
| `wifi LOST` 一直跳 | **不要重啟板子。** 送 `P wifiRetryMs 30000` 把重試間隔拉大 |
| `EV url not set` | 位址沒設，回第一步 |
| `http` 是負數 | 位址錯了。送 `G url` 看實際存了什麼——**先確認 port 有沒有打在裡面** |
| `http 200` 但 `DATA` 是空的 | 按手柄上的 X 再抓一次 |
| 左下角什麼都沒有 | 有點到手柄上的 X 嗎？再按一次 |

### 複查清單

- [ ] 接上板子時，留意開序列埠會不會讓板子重啟（會的話要等 3 秒）
- [ ] 在實驗室先跑完整一次
- [ ] 這條流程還沒在真板 + 真塔上跑過，實驗室那次當第一次

## Mission 2.1：AprilTag 掃描（40 分）

**要做的**：掃描場上三個 AprilTag，把裁判當天指定的邏輯（最大 or 最小）算出來的那個 ID 報給裁判。

**分數**：邏輯對 = 10 分，三個 tag 各 10 分，共 40 分。
**邏輯選錯、或沒把答案顯示出來 = 0 分。**

### 一、進模式

1. **按手柄上的 A**
2. 左下角出現 `SELECTION LOGIC NOT SET`

### 二、選邏輯（裁判當天唸給你）

裁判會告知今天要**最大的 ID** 還是**最小的 ID**：

- **按鍵盤上的 L** = 取最大
- **按鍵盤上的 M** = 取最小

選完左下角會顯示 `logic largest (L)` 或 `logic smallest (M)`。

> **沒選之前，按手柄上的 RB 不會有反應。** 猜錯邏輯是零分，所以程式寧可不動，也不給預設值。

### 三、掃描（重複三次）

1. 把 ROV 開到三個 tag 都看得到的位置
2. **按手柄上的 RB** —— 拍一拍，約 0.3 秒
3. 左下角 `captures` 加一，`ids` 多一個號碼

再按一次 RB 就再拍一次，直到 `captures 3/3`。

```
MODE  AprilTag
logic    largest   (L)
captures 2/3
ids      [3, 7]
RESULT   7
```

### 四、報答案

看 `RESULT` 那一行，唸給裁判聽。拍到第三次會多一個 `DONE`。

### 沒成功時

| 看到 | 怎麼辦 |
|---|---|
| `SELECTION LOGIC NOT SET` | 還沒選邏輯。按鍵盤上的 L 或 M |
| 按手柄上的 RB 沒反應 | 同上，先選邏輯 |
| `captures` 沒有加 | 那一拍沒看到 tag。**不佔次數**，再拍一次就好 |
| `ids` 只有一兩個號碼 | 拍到重複的 tag 了，見下面第一條 |
| 想重來 | 按**鍵盤上的 R** —— 清掉掃描結果，但**保留邏輯** |

### 三個一定要記住的

**① `ids` 那個集合才是重點，不是 `captures` 的次數。**

三次都拍到同一個 tag，`ids` 就只有一個號碼，答案是錯的。
**要拍到的是三個不同的 tag**，不是拍滿三次。

**② `RESULT` 從第一次拍到就開始算。**

如果兩次就湊齊三個 ID，不用硬拍第三次。

**③ 按手柄上的 A 回 Manual 再進來，會全部重來，包括邏輯。**

因為每次上場裁判都會重新告知，留著上一次的邏輯是危險的。

### 複查清單

- [ ] **邏輯按對了嗎？**（最大 = 鍵盤上的 L，最小 = 鍵盤上的 M）——這是唯一會直接零分的選擇
- [ ] `ids` 裡有三個**不同**的號碼嗎？
- [ ] 掃描時畫面沒有凍結，搖桿一直都能操縱
- [ ] 還沒在真攝影機 + 真 tag 上跑過（只在合成畫面上測過）

## Mission 2.2：艙室停靠（20 分）

**要做的**：把 ROV 開進正確的那個艙室，過程中不要碰到任何東西。

| 結果 | 分數 |
|---|---|
| 順利開進去，全程沒碰到牆或入口 | 20 |
| 開進正確的艙室，但碰到了（含纜線、機械臂、機架） | 10 |
| 開錯艙室、沒開完、或放棄 | 0 |

**純手動，程式不參與。** 哪個艙室是對的由場地佈置決定，畫面只給你看位置。

> 分數全部來自操縱的精準度，沒有任何辨識或自動功能可以幫你。

## Mission 3：循線（30 分）

**要做的**：沿著池底的黑線開，依序通過檢查點，最後到終點。

| 到達 | 分數 |
|---|---|
| 通過 Checkpoint 1 | 10 |
| 通過 Checkpoint 2 | 10 |
| 到達終點線 | 30 |

**只有最高的那個算，不累加。** 走到終點就是 30 分，不是 10+10+30。

**必須手動操縱**，但允許軟體輔助——手冊明文寫「including human-operated PID control」，
只要最終控制權在人手上就行。

> ⚠️ **程式目前完全沒有循線功能。** 沒有偵測黑線、沒有任何輔助。
> 這一項只能靠手動開。如果要加輔助，要另外寫。

## Mission 4：物件回收（40 分）

**要做的**：從起點出發，用鉤子把池底的目標物勾起來，帶回起點放開。

| 結果 | 分數 |
|---|---|
| 勾住 → 帶回起點 → 放開 | 40 |
| 勾住後**離地 3 秒** | 20 |
| 只碰到、沒勾住 | 0 |

**中途掉了**：已經達成過 3 秒離地的話，保留那 20 分。還沒滿 3 秒就掉了 = 0 分。

**純手動**，允許軟體輔助。官方可能會把目標物的孔加大方便勾取。

## Mission 5：顏色桿辨識與擊打（50 分）

**要做的**：找出紅、黃、藍三根桿子，把它們的球打下來。

| 結果 | 分數 |
|---|---|
| 每打下一根桿子的球 | 10（最多 30） |
| **完全照裁判給的順序**打完三根 | **+20** |
| 三根都打到但順序不對 | 只有 30，沒有獎金 |

**擊打是純手動操縱**，程式不參與。程式只負責**辨識顏色**。

> ⚠️ **順序由你記，程式不管。** 裁判喊的順序每次可能不同，程式沒有地方可以輸入，
> 所以畫面不會顯示，也不要指望它。**裁判喊完就寫在紙上或記牢。**

---

### 一、進模式

1. **按手柄上的 B**
2. 左下角出現 `MODE  Colour`

### 二、校準（第一次用，或換了場地才要做）

顏色閾值**必須在真實泳池校準**，程式裡的預設值只是起點。

1. 把**滑鼠游標移到純桿身**上（不要指邊緣，也不要指到池底）
2. 按鍵盤上的數字鍵：

   - **`1`** = 紅　**`2`** = 黃　**`3`** = 藍

3. 終端會印 `R calibrated from the pointer`，並存成檔案，下次不用重做

> 校準取的是游標周圍 31×31 像素，所以**準星要對準桿身正中**。
> 指偏了會得到一組不對的閾值，而且它不會報錯。

### 三、辨識顏色

1. 把**滑鼠游標移到要辨識的桿子上**——畫面上會有一枚**青色十字準星**標出程式認為你在指哪裡
2. **按手柄上的 RB**
3. 畫面**最下方**用該顏色的字印出答案：

   ```
   color recognition = RED
   ```

**畫面不會凍結。** 你在瞄準的時候需要看得到即時影像。

> **游標離開視窗位置會保留。** 瞄好之後手移到手柄上按 RB，程式用的還是你最後指的那一點。

### 四、打下來

1. 記住顏色，把 ROV 開過去把球打下來（**這一段是純手動操縱**）
2. 照裁判喊的順序，一根一根來

**程式不追蹤你打到第幾根，也不記順序。** 那是你的工作。

### 沒成功時

| 看到 | 怎麼辦 |
|---|---|
| 畫面底部沒有答案 | 沒辨識出來。瞄準桿身正中，再按一次 |
| `too few coloured pixels` | 指到灰色池底了 |
| `sample is too colour-mixed` | 指到兩根桿子中間的接縫了 |
| 答案顏色不對 | 閾值要重新校準（回步驟二） |
| 按 RB 沒反應 | 游標要先在畫面上出現過一次 |

> **這是取樣，不是偵測。** 程式不判斷「那根桿子像不像桿子」，只看你指的那一塊是什麼顏色。
> **指到藍色池底油漆就會回報 BLUE。**

### ⚠️ 順序要自己記

裁判喊的順序**每次可能不一樣**（例如 `Y-R-B`），而且只有完全照著做才有那 20 分獎金。

**程式沒有地方輸入這個順序，畫面也不會顯示它。**
（舊版畫面曾經顯示一行 `order R-B-Y`，但那是寫死的常數，不是裁判喊的——
照著做反而一定拿不到獎金，所以拿掉了。）

**裁判喊完立刻記下來。** 打的時候照著這個順序走。

### 複查清單

- [ ] 閾值在真實泳池校準過了嗎（不要在實驗室的桌面燈光下校準就上場）
- [ ] **裁判喊的順序記下來了嗎**（程式不會幫你記）
- [ ] 三根桿子的位置確認過了嗎
