# UWR ROV 操作指南

從零到能動，照順序做。每一步都有驗證方法，過了再往下走。

---

## 0. 系統長什麼樣

```
Xbox 手柄 ──USB──> 筆電 ──序列埠──> ESP32 ──PWM──> 兩個電調 ──> 推進器
   │                │                  │
   │                │                  └── Wi-Fi + HTTP（Mission 1，板子自己做）
   │                └── 攝影機、畫面、辨識
   └── 所有按鍵都在這裡讀
```

**手柄和影像在筆電，馬達和 Mission 1 在板子。** 筆電的程式當掉不會讓 ROV 失控，
因為兩道安全防線都在板子裡。

## 1. 準備

### 硬體

| 東西 | 備註 |
|---|---|
| ESP32-S3 | N16R8（16 MB）或 N8R8（8 MB） |
| 兩個電調 + 兩個推進器 | 電調另外要接動力電池 |
| Xbox 手柄 + USB 線 | 有線最省事 |
| 攝影機 | 筆電內建的就夠 |
| 杜邦線 | 電調**地線必須接回 ESP32 的 GND** |

### 接線

| 電調細線 | 接到 |
|---|---|
| 訊號（白／橙） | 左 **GPIO4**、右 **GPIO7**、垂直 **GPIO8** |
| 地（黑／棕） | GND |
| 電源（紅，BEC 5V） | **留空不接** |

三路電調**共用一個 `neutral` 參數**（`P neutral 1500` 會同時改三路）。同型號沒問題，
混用不同型號要注意。

### 裝軟體

**Windows**

```bash
python -m pip install -r host\requirements.txt
```

Python 用 python.org 的 3.11，安裝時勾「Add python.exe to PATH」。
PlatformIO 用 VS Code 的擴充（「開啟資料夾」打開 `firmware\ESP32`），
或用命令列 `python -m pip install platformio`。

> **Windows 上要送指令給板子**（`P url …`、`G ssid` 那些），
> 步驟、指令、以及怎麼認出正確的 COM 埠，見
> [比賽操作手冊的附錄](OPERATION-MANUAL.md#附錄送指令給板子)。

**macOS / Linux**

```bash
python3 -m pip install -r host/requirements.txt
```

> `pip install` 要裝進**你實際拿來跑的那個 python**。機器上常有好幾個 python，
> 裝進一個、用另一個跑，是最常見的「我明明裝了啊」。

**驗證**

```bash
python3 -m unittest discover -s host -t host
```

看到 `OK` 就對了。這一步不需要手柄、不需要板子、不需要攝影機——
所有檢查都跑在假的控制器上。

## 2. 燒韌體

在 repo 根目錄執行，`-d` 指出專案在哪：

```bash
pio run -d firmware/ESP32 -t upload
```

**兩種板子都是這條指令**——N8R8（8 MB）和 N16R8（16 MB）都一樣，不用切換、
不用先確認桌上放的是哪一塊。

分割表固定用 8 MB：它在 N16R8 上跑得起來，只是用不到上面一半（韌體本體約
1 MB，那 8 MB 本來也空著）。**反過來才會出事**——16 MB 的分割表燒進 8 MB
的晶片會做出開不了機的映像，所以那個選項沒有留著。

埠認不出來就明講：`pio run -d firmware\ESP32 -t upload --upload-port COM5`（Windows）
或 `--upload-port /dev/cu.usbserial-XXXX`（macOS）。

**驗證**：燒完打開序列埠監視器（115200），應該每 50 ms 刷一行 `JOY`。

## 3. 脫槳測試（第一次一定要做）

> **先拆槳。** 手邊留著電源開關。

1. 只給 ESP32 上 USB 電，**電調的動力電先不要接**
2. 跑 `python3 host/pad_bridge.py --show-input`，推左搖桿
   - 推上 → `Y` 要是**正**數
   - 推右 → `X` 要是**正**數
   - 不對的話記下來，先別往下走
3. 記下你按的鍵對應的編號（A / B / X / RB 各是幾號）
4. 接上電調動力電
5. 跑 `python3 host/console.py`
6. 畫面右下角會顯示 `Y Lock [LOCKED]`——安全鍵是 **Y**，此時是鎖著的。
   按一下 Y 解鎖，再輕推搖桿

**驗證**：兩個馬達都轉，而且方向正確。轉向反了就兩根相線對調。

## 4. 操作

```bash
python3 host/console.py
```

畫面：中間是攝影機，四角是狀態。

```
┌──────────────────────────────────────────────┐
│ ● LINK   UNLOCK        L   +44%  ███████░░░   │  左上 連線 + 安全鍵
│                        R   -56%  █████░░░░░   │  右上 三路油門（0% 在中間）
│                    CAMERA                    │  中間 攝影機
│ MODE  AprilTag         A  AprilTag   [ON]    │  左下 目前任務
│ ID 07  dist 1.24 m     B  Colour     [  ]    │  右下 按鍵
│ CONF 0.93              X  WiFi       [  ]    │
│                        RB Lock       [LOCKED]│
└──────────────────────────────────────────────┘
```

| 按鍵 | 功能 |
|---|---|
| **左搖桿** | 前後推進、左右轉向 |
| **RT** | **上升**（脈寬 1500 → 2000） |
| **LT** | **下潛**（脈寬 1000 → 1500） |
| **A** | 切到 AprilTag 模式（Mission 2.1） |
| **B** | 切到顏色模式（Mission 5） |
| **X** | 切到 WiFi 模式（Mission 1） |
| **RB** | **拍一張**——在目前模式下辨識一次 |
| **Y** | 安全鍵（解鎖／上鎖） |

鍵盤：**Q**／**Esc** 離開、**S** 存一張 PNG、**T** 打板子指令（Mission 1 設位址用）。
按 `T` 之後左上角出現 `>`，打完按 **Enter** 送出，板子的回覆就顯示在那裡。

**兩支扳機同時按下去 = 停。** 那是一個自相矛盾的指令，所以垂直推進器回 1500，
而不是挑一個方向猜。垂直推進器的錯誤方向比不動更糟。

**A / B 只切模式，不做事。** 切過去之後畫面是即時預覽、不跑任何計算；**按 RB 才
辨識一次**，結果凍結在那一幀停住不跟著鏡頭飄；再按一次 RB 就重拍。

X 模式例外，它顯示的是板子主動回報的 Mission 1 狀態，不需要觸發。

再按一次 A / B 回到 Manual。**搖桿永遠都能驅動**，切任務不影響。

視窗裡按 `Q` 或 `Esc` 離開。

### 顏色模式：游標指哪就辨識哪（Mission 5）

```
按 B → 游標指著桿子 → 按 RB → 畫面底部出現 color recognition = RED
```

1. 按 **B** 進模式
2. 把**滑鼠游標移到要辨識的桿子上**。游標位置會有一枚**青色十字準星**標出來，
   那代表程式認為你在指哪裡
3. 按 **RB**，畫面正下方用**該顏色的字**印出答案：

   ```
                    ┌────────────────────────────┐
                    │  color recognition = RED   │
                    └────────────────────────────┘
   ```

**不凍結畫面**——你在瞄準的時候需要看得到即時影像。

**判定方式**：取游標周圍 15×15 像素，要求

- **至少四成是彩色**——灰色池底、白色反光會被排除
- **至少六成落在同一個顏色**——門檻設在明顯過半，是為了讓「指在兩根桿子的接縫上」
  回報「沒有答案」，而不是挑一個剛好多幾像素的顏色

不符合就顯示 `--`，終端也會說明原因。

> 這是**取樣**不是**偵測**：程式不判斷「那根桿子像不像桿子」，只看你指的那一塊
> 是什麼顏色。**指到藍色池底油漆就會回報 BLUE。** 答案的好壞取決於你瞄得準不準。

| 鍵 | 作用 |
|---|---|
| `C` | 跟 RB 一樣：辨識一次 |
| `1` `2` `3` | 游標指著純桿身按下去，校準紅／黃／藍（會存檔） |
| `R` | 清掉答案 |
| `D` | 顯示顏色遮罩除錯視窗 |

顏色閾值**必須在真實泳池校準**，預設值只是起點。

> **擊打順序由裁判當天宣布，而且每次可能不同，程式不追蹤它。**
> 早期版本畫面顯示過一個固定順序，但那是寫死的常數而不是裁判喊的，
> 照著做只會拿不到順序獎金，已經拿掉。**自己記。**

> **校準也是指向式的**：游標指著桿子，按 `1`（紅）／`2`（黃）／`3`（藍）就好，
> 不用拖框、不會彈出第二個視窗。它取游標周圍 31×31 像素來算閾值。
>
> ⚠️ 這表示校準樣本比原本小。如果桿子很細或游標偏了，會得到一組不對的閾值——
> 按 `1`/`2`/`3` 之前先把準星對準杆身正中。

> **游標離開視窗位置會保留。** 瞄好之後手移到手柄上按 RB，程式用的還是你最後
> 指的那一點。

### AprilTag 的完整流程（Mission 2.1）

```
按 A → 選邏輯（L/M）→ 拍三次（RB）→ 看結果
```

1. 按 **A** 進模式。左下顯示 `SELECTION LOGIC NOT SET`
2. 裁判會告知要最大的還是最小的 ID：
   - 按 **L** = 最大的 ID（largest）
   - 按 **M** = 最小的 ID（smallest）

   **沒選之前 RB 不會動作。** 猜錯邏輯是零分，不能讓它默默用一個預設值。
3. 每按一次 **RB** 拍一次（約 0.3 秒），把確認到的 ID 併進集合
4. 左下角即時更新：

   ```
   MODE  AprilTag
   logic    largest  (L)
   captures 2/3
   ids      [3, 7]
   RESULT   7
   ```

5. 拍到第三次標 `DONE`。**結果從第一次拍到就開始算**——如果兩次就湊齊三個 ID，
   不用硬拍第三次。
6. 按 **R** 重新掃（保留邏輯）。按 **A** 回 Manual 再進來則**全部重來**，
   包含邏輯（因為每次上場裁判都會重新告知）

**畫面不會凍結。** 掃描的時候你還是要操縱 ROV，凍結的畫面沒有用。框只在拍照
那一瞬間畫出來，收到什麼 ID 留在左下面板。

**空拍不算次數。** 沒看到任何 tag 的那一拍不會佔用三次配額。

> ⚠️ **三次拍照 ≠ 三個不同的 tag。** 可能三次都拍到同一個，也可能一次就拍到三個。
> 真正決定結果的是 **`ids` 那個集合**，不是次數。拍完看一下集合裡有幾個，
> 不對就按 R 重來。

### 各拍幾幀

| | 拍多久 | 確認條件 |
|---|---|---|
| AprilTag | 約 0.3 秒 | 同一 ID 要在 ≥2 幀出現 |
| 顏色 | 約 1 秒 | 候選要在 ≥60% 的幀出現，且最後一幀仍看得到 |

AprilTag 取兩幀而不是一幀，是因為單幀被水波晃糊就整個認不出來。

> 框選 ROI 或校準時會彈出選取視窗，那幾秒鐘驅動迴圈會暫停，板子的斷流保護
> 會把馬達送回中立。這是安全的方向——你在框框的時候本來就沒在操縱。

### 攝影機

**畫面是上下顛倒的，這是正常的。** 攝影機在 ROV 上是倒著裝的，
所以每一格畫面在進到程式時**立刻轉 180 度**（[console.py](../host/console.py) 的 `upright()`），
最後看到的影像是正的。

> 反過來說：**如果你在實驗室用筆電內建攝影機測試，畫面會是顛倒的。**
> 那不是壞掉——程式假設攝影機永遠是 ROV 那個裝法。
> 面板和文字不會跟著翻，只有攝影機影像會。

> 滑鼠座標跟畫面上看到的一致。翻轉在**最前面**做完，所以準星指哪裡，
> 程式就取樣哪裡——這是把翻轉放在那個位置的唯一理由。

**不確定哪一支能用，先列出來：**

```bash
python3 host/console.py --list-cameras
```

它依序試 0~5，列出每個回報的解析度。開得起來但沒有畫面的會標註
（有些虛擬攝影機就是這樣）。什麼都沒有時它會提醒你去檢查系統的攝影機權限——
**被拒絕的權限和「沒有攝影機」在程式裡長得一模一樣**。

**指定要用哪一支：**

```bash
python3 host/console.py --camera 1
```

指定的編號如果不在，程式會**往後找**其他編號，並在終端印出實際用的是幾號。

**掉線會自己接回來。** 攝影機被拔掉、或被 Teams／Zoom 搶走時：

- 左上方出現紅色 **`NO CAMERA`**
- 每秒重試一次**原本那個編號**
- 插回去畫面自己恢復，終端印 `camera N reconnected`

> **只重試原本那個編號。** 如果它去抓筆電內建那支，你會看到天花板而不是水池——
> 那比沒有畫面更糟。編號真的變了就重跑 `--list-cameras`。

> **讀取跑在背景執行緒。** 這樣攝影機卡住不會拖住主迴圈——主迴圈一停就送不出
> 驅動指令，板子會把馬達切到中立。重連要花好幾秒，這幾秒你不能失去操控。
> 這也是「自動重連」做得到的前提。

> **`1280×720` 是請求不是保證。** 驅動可以給你別的尺寸。**低於 720p 的話四角
> 面板會擠在一起**，因為版面用的是固定像素偏移。

## 5. 安全規則（必讀）

馬達沒有「解鎖後就一直是活的」這回事，四道閘都在板子裡：

| 閘 | 行為 |
|---|---|
| 安全鍵 | 預設鎖著，按一下解鎖。**手柄掉線自動重新鎖上** |
| 斷流保護 | 200 ms 沒收到指令就強制回中立 |
| 開機預熱 | 上電後 3 秒內不理輸入 |
| 油門限速 | 脈寬每毫秒最多變 2 µs，不會啪一下滿油門 |

**四條一定要記住的**

1. **測試一律拆槳。** 手邊留著電源開關。
2. **第一次通電前確認電調中立位。** 雙向電調是 1500，單向是 1000。猜錯的話上電瞬間
   螺旋槳直接全速轉——這是唯一來不及斷電的情況。改 `firmware/ESP32/src/config.h`
   的 `ESC_US_NEUTRAL`，或現場用 `P neutral 1000` 改。
3. **電調和 ESP32 必須共地。**
4. **電調的 BEC 5V（紅線）不要接**，那是 5V，ESP32 的 GPIO 是 3.3V。

## 6. 比賽當天

**出發前先確認 `ssid` 是大會公布的那個**（送 `G ssid`）。

`P` 指令改過的 `ssid` / `pass` 會**永久**存在晶片裡，重新燒錄也不會清掉。不先確認的話，
板子到了場地會悶頭去連家裡那個網路，連不上就是 Mission 1 直接零分，而且現場幾乎
想不到是這個原因。

> **比賽的 Wi-Fi 已經編譯在裡面**（`params.h`）：`CityUHK_UR_Fall-Training` /
> `UnderwaterRobotic2026`。這是大會發給所有隊伍的共享憑證，不是私人秘密，所以公開
> 放在倉庫裡。**要改就 `P ssid` / `P pass`**，會存進 NVS 蓋掉預設值。

> ⚠️ **不要用 `R` 來清。** 它不只清 Wi-Fi——`neutral`、`trimL`、`trimR`、`trimV`、
> `fsMs` 會一起打回預設值，實驗室校準過的配平就沒了。要改哪一項就 `P` 哪一項。

連不上塔時**不要反覆重啟**，把重連間隔調大：

```
P wifiRetryMs 30000
```

家用路由器對短時間內反覆連線的裝置有防抖機制，越急越連不上。

## 7. 常見問題

| 現象 | 檢查 |
|---|---|
| 上電馬達就轉 | 電調中立位猜錯了。斷電，改 `ESC_US_NEUTRAL` |
| 推桿沒反應 | 還在 3 秒預熱內；或安全鍵沒解鎖；或序列埠斷流 |
| 只有一個馬達轉 | 另一路的訊號線或共地沒接好 |
| 馬達轉向相反 | 馬達線兩兩對調（無刷馬達任意對調兩根相線） |
| 左右轉方向反了 | 先跑 `--show-input` 確認軸符號，**先別改韌體** |
| 序列埠收到的行殘缺 | 埠被別的程式佔著（序列埠監視器、另一個 console） |
| 序列埠全是亂碼 | 鮑率不是 115200 |
| 燒錄後反覆重啟 | 有東西接到 GPIO33~37（PSRAM 佔用） |
| 攝影機開不起來 | 被 Teams / Zoom 佔著，先關掉 |
| `command not found: pio` | macOS：`~/.platformio/penv/bin/pio`。Windows：`python -m platformio`，或裝 VS Code 擴充 |
| **PowerShell 說 `&&` 不是有效的分隔符號** | Windows 內建的是 PowerShell 5.1，**不支援 `&&`**。用 `;` 或分成兩行 |
| `pio` 被 Application Control 擋掉 | 改用 VS Code 的 PlatformIO，或 `python -m platformio` |
| 找不到序列埠 | 只有一個埠插著時自動偵測一定找得到；兩個都插的話用 `--port` 指定 |

## 8. 還沒做的事

- 顏色辨識的 HSV 閾值還沒在真實泳池校準過，預設值只是起點
- 轉向方向與電調行程還沒在真船上驗證過
- 只有一個 Tag 在畫面裡測過；多個 Tag 同時出現的實景還沒試

### 驗證程式

```bash
python3 -m unittest discover -s host -t host -v
```

102 項，不需要攝影機、不需要板子、不需要手柄——所有硬體都由測試檔自己的替身
代替。涵蓋手柄軸向與扳機、安全鍵開關、序列埠挑選、JOY 解析、標籤偵測、多幀
確認、游標取樣、HSV 校準與設定檔往返，以及兩條完整流程：「待命 → 選邏輯 →
按 RB 收 ID → 套用邏輯」和「游標指向 → 按 RB → 得到顏色」。
