# UWR ROV 控制系統

CityUHK UR Fall Training 2026 水下 ROV 的控制與視覺程式。

> **第一次上手請先看 [操作指南](docs/GUIDE.md)** —— 從裝軟體到讓馬達轉起來的完整
> 步驟，照順序做就好。這份 README 是參考資料，指南是操作流程。

## 系統分工

```
Xbox 手柄 ──USB──> 筆電 ──序列埠──> ESP32 ──PWM──> 兩個電調 ──> 推進器
   │                │                  │
   │                │                  └── Wi-Fi + HTTP（Mission 1，板子自己做）
   │                └── 攝影機、視覺辨識、畫面顯示
   └── 所有按鍵都在這裡讀
```

**為什麼是這樣分**：ROV 上只允許一塊 ESP32，而它既沒有攝影機也算不動視覺。
所以手柄和影像處理都留在筆電，ESP32 只負責三件事——收指令、驅動推進器、
自己連 Wi-Fi 取 Mission 1 的資料。筆電上的程式壞掉不會讓 ROV 失控，
因為兩道安全防線都在板子裡。

## 硬體接線

| 部件 | 接到 ESP32-S3 |
|---|---|
| 左電調訊號線（白／橙） | **GPIO4** |
| 右電調訊號線 | **GPIO5** |
| 電調地線（黑／棕） | GND |
| 電調 BEC 電源線（紅） | **留空不接**（電調自己從動力電取電） |

電調另有兩根粗線接動力電池（XT60），三根粗線接馬達。

**電調的中立位必須先確認**，改 `firmware/ESP32/src/config.h` 的 `ESC_US_NEUTRAL`：

| 電調類型 | 中立位 |
|---|---|
| 雙向（能反轉，ROV 一般用這種） | `1500` ← 預設 |
| 單向（只能正轉） | `1000` |

> 猜錯的後果是**上電瞬間螺旋槳全速旋轉**。第一次通電一定先拆槳。

### 兩個容易踩的坑

**ESP32 和電調必須共地。** 訊號是相對 GND 的電壓，不共地電調收到的是雜訊。

**要避開的腳位**：GPIO26~32（板載 SPI Flash）、GPIO33~37（Octal PSRAM）、
GPIO19/20（原生 USB）、GPIO43/44（UART0）、GPIO0/3/45/46（strapping）。
韌體只用 4 和 5，兩個都在排針上。

## 安全機制

馬達沒有「解鎖／上鎖」狀態機，改成兩道閘，兩道都在韌體裡，筆電程式掛掉也有效：

1. **安全鍵（開關式）**：預設鎖住，按一下解鎖、再按一下鎖上。
   手柄一掉線自動重新鎖上。
2. **斷流保護**：連續 200 ms 沒收到合法指令就強制回中立。
   線掉了、程式崩了、筆電睡了，都會觸發。

另外兩道是開機與輸出層的：

3. **開機預熱 3 秒**：上電後頭 3 秒把輸入當作沒動，等電調自檢完、
   手也放好了才開始響應。
4. **油門限速**：脈寬每毫秒最多變 2 µs，從中立到全油門要約 250 ms，
   不會「啪」一下滿油門。

> 測試時**一律拆槳**，手邊留著電源開關。

## 搖桿 → 雙馬達映射

```
前後 = ny        左右 = nx
左 = 前後 + 方向 × 左右        右 = 前後 − 方向 × 左右
                                  ↑ 後退（ny<0）時方向取反
```

| 搖桿 | 左 | 右 | 效果 |
|---|---|---|---|
| 置中（死區內） | 1500 | 1500 | 停 |
| 前推到底 | 2000 | 2000 | 兩路同速前進 |
| 後拉到底 | 1000 | 1000 | 兩路同速後退 |
| 原地推右 | 2000 | 1000 | 左路出力多 → 船頭右轉 |
| 原地推左 | 1000 | 2000 | 右路出力多 → 船頭左轉 |
| 前進中推右 | 2000 | 1500 | 船頭往右偏 |
| **後退中推右** | 1000 | 1500 | **船尾往右走** |

後退時左右取反是**方向盤慣例**：推右時不論前進或後退，船身都往右漂。
不取反就是「坦克慣例」（不論方向一律順時針轉），兩種都自洽，這裡選前者。

## 快速開始

### 韌體

```bash
cd firmware/ESP32
~/.platformio/penv/bin/pio run                 # 編譯
~/.platformio/penv/bin/pio run -t upload       # 燒錄
```

有兩個建置環境，差別只在 Flash 分割表：

| 環境 | 對應板子 | 指令 |
|---|---|---|
| `uwr-rov`（預設） | **N8R8**（8 MB）——實驗室那塊 | `pio run -t upload` |
| `uwr-rov-16mb` | **N16R8**（16 MB） | `pio run -e uwr-rov-16mb -t upload` |

> 8 MB 的設定也能燒進 16 MB 的板子（只用到下面 8 MB），所以預設值是安全的。
> **反過來不行**：16 MB 的分割表燒進 8 MB 的晶片會做出開不了機的映像。
> 不確定手上是哪塊，就用預設值。

### 筆電端

```bash
pip install pygame pyserial

# ① 先認軸和按鍵（只讀手柄，不碰序列埠）：推搖桿、按各鍵，看哪個編號在動
python3 host/pad_bridge.py --show-input

# ② 正常跑。啟動時按一下你想當安全鍵的按鍵（它自己學編號），
#    然後預設是鎖住的：按一下解鎖，再按一下鎖上
python3 host/pad_bridge.py

# ③ 第一次除錯不想管鎖
python3 host/pad_bridge.py --no-deadman

# ④ 不接板子，只測手柄
python3 host/pad_bridge.py --no-serial
```

不接手柄也能驗證程式邏輯：

```bash
python3 host/pad_bridge.py --selftest
```

### 操作台（OSD）

```bash
python3 host/console.py
```

一個行程同時握著手柄、攝影機和序列埠，畫面是 DJI 那種版面——中間是攝影機
影像，四角是狀態面板：

```
┌──────────────────────────────────────────────┐
│ ● LINK   UNLOCK        L 1718  ▓▓▓▓▓▓▓▓░░    │  左上 連線 + 安全鍵
│                        R 1282  ▓▓▓▓▓▓░░░░    │  右上 兩路實際輸出脈寬
│                                              │
│                    CAMERA                    │  中間 攝影機影像
│                                              │
│ MODE  AprilTag         A  AprilTag   [ON]    │  左下 目前任務與結果
│ target   7             B  Colour     [  ]    │  右下 按鍵提示
│ scanned  1/3           X  WiFi       [  ]    │
│ ids      [7]           Y  Lock       [LOCKED]│
└──────────────────────────────────────────────┘
```

**為什麼是一個行程而不是每個功能一支程式**：攝影機同一時間只能被一個行程
打開；開 OpenCV 加暖機要一兩秒，比賽按一下鍵等不起；兩個行程搶同一支手柄也
很亂。按鍵只在這個迴圈裡切換「目前任務」，50 Hz 的驅動迴圈照跑，所以換模式
時馬達不會卡頓。

**任務只決定畫面顯示什麼和攝影機拿來做什麼，搖桿永遠都能驅動。**

| 按鍵 | 功能 |
|---|---|
| **A** | AprilTag 辨識（Mission 2.1） |
| **B** | 顏色辨識（Mission 5） |
| **X** | WiFi／Mission 1（順便讓板子立刻重取一次資料） |
| **Y** | 安全鍵（解鎖／上鎖開關） |

再按一次同一個鍵就回到 Manual。按鍵編號用 SDL 標準對應，第一次用真手柄跑之前
先 `python3 host/pad_bridge.py --show-input` 核對一下。

沒有硬體也能跑或檢查版面：

```bash
python3 host/console.py --synthetic      # 沒有攝影機，用測試圖樣
python3 host/console.py --no-serial      # 沒有板子
python3 host/console.py --render-preview .preview   # 輸出各狀態的版面 PNG
```

### 在另一台電腦上（Windows）

第一次在新機器上跑，只有這幾點不一樣：

**1. Python 依賴**

```bash
python -m pip install -r host\requirements.txt
```

裝 python.org 的 3.11，安裝時勾「Add python.exe to PATH」。

**2. PlatformIO**

最省事是用 VS Code 的 PlatformIO 擴充（用「開啟資料夾」打開 `firmware\ESP32`）。
要用命令列就 `python -m pip install platformio`，之後 `pio` 就在 PATH 上。

**3. 序列埠是 `COMx`，不是 `/dev/cu.*`**

程式會自動認：macOS 靠埠名（`cu.usbserial-*`），Windows 靠**描述**（`USB Serial
Port`、`USB-SERIAL CH340`、`Silicon Labs CP210x`…），因為 Windows 的埠名只有
`COM5` 這種。認不出來它會列出所有候選，再手動指定：

```bash
python host\console.py --port COM5
```

**4. 驅動**

板載橋接晶片要用對應的驅動：FT232RL → FTDI VCP，CH34x → WCH。Windows 10 以上
多半會自動裝好；裝置管理員裡該埠有驚嘆號就是沒裝。

**5. 攝影機**

`console.py` 在 Windows 上走 DirectShow，比預設後端快很多（預設的要好幾秒才開，
看起來像當掉）。被 Teams、Zoom 這類程式佔著會開不起來，先關掉。

**6. 燒錄**

`pio` 通常自己找得到埠；找不到就明講：

```bash
pio run -e uwr-rov-16mb -t upload --upload-port COM5
```

## 序列埠協定

純 ASCII 行協議，用序列埠監視器就能手動發指令、肉眼讀回覆。

### 筆電 → ROV

| 指令 | 說明 |
|---|---|
| `CMD nx=<f> ny=<f> en=<0\|1>` | 驅動。`nx`/`ny` 為 −1~+1，推右為正、推上為正。`en=1` 表示已解鎖。每 20 ms 一行 |
| `P <key> <value>` | 寫參數（存 NVS，掉電不丟） |
| `G [<key>]` | 讀一個參數；不帶參數則列出全部 |
| `R` | 恢復預設參數 |
| `W` | 立刻連 Wi-Fi |
| `F` | 立刻去 HTTP 取一次資料 |
| `S` | 查詢狀態 |
| `B` | 重啟 |

**比賽當天開機先發一條 `R`**，清掉實驗室測試留下的 Wi-Fi 設定。
`P` 指令改過的 `ssid`/`pass` 會**永久**存在晶片裡，重新燒錄也不會清掉
（NVS 在 Flash 的獨立分區）。不先清掉的話，板子到了場地會悶頭去連家裡
那個網路，連不上就是 Mission 1 直接零分，而且現場幾乎想不到是這個原因。

### ROV → 筆電

| 行 | 說明 |
|---|---|
| `OK` / `ERR` / `EV` | 指令結果／錯誤／事件 |
| `DATA <text>` | Mission 1 取到的內容，要顯示給裁判看 |
| `JOY ...` | 驅動遙測，每 50 ms 一行 |
| `ST ...` | Mission 1 狀態（Wi-Fi、IP、HTTP 碼），每 500 ms 一行 |

`JOY` 這行是之後畫面的資料來源：

```
JOY X=+0.420 Y=-0.170 MAG=0.542 OUT READY=1 L=1718 R=1282 TL=1718 TR=1282 EN=1 LINK=1
```

`L`/`R` 是**實際寫給電調的脈寬**（經過限速），`TL`/`TR` 是搖桿算出的目標值。
兩者不相等代表正在加減速。新增欄位一律追加在行尾，舊的解析器會忽略。

## 除錯

| 現象 | 檢查 |
|---|---|
| 上電馬達就轉 | 電調中立位猜錯了。斷電，改 `ESC_US_NEUTRAL`（單向電調是 1000） |
| 推桿沒反應 | 還在 3 秒預熱內；或安全鍵沒解鎖（`en=0`）；或序列埠斷流 |
| 只有一個馬達轉 | 另一路的訊號線或共地沒接好 |
| 馬達轉向相反 | 馬達線兩兩對調（無刷馬達任意對調兩根相線） |
| 左右轉方向反了 | 先確認手柄的軸符號（跑 `--show-input`），**先別改韌體** |
| 序列埠收到的行殘缺、兩行黏在一起 | 埠被別的程式占著：`lsof /dev/cu.usbserial-*` |
| 序列埠全是亂碼 | 鮑率不是 115200（序列埠會殘留上一個程式的設定） |
| 燒錄後反覆重啟 | 有東西接到 GPIO33~37（PSRAM 腳） |
| 連不上塔 | 先看 `ST` 行的 `wifi=`；別反覆重啟，改 `P wifiRetryMs 30000` |

### 已知問題（下水前要處理）

- `P`／`R` 指令會在主迴圈裡寫 NVS。NVS 寫入是阻塞的，會讓馬達控制與
  斷流保護一起暫停；暫停期間 PWM 凍結在最後一個油門值。
  需要把 NVS 寫入移到 core 0 的任務，或改用與主迴圈無關的斷流計時。
  台面測試階段以拆槳 + 手邊電源開關兜底。
